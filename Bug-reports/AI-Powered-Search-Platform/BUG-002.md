# BUG-002 – Persistent "Processing" loader and missing frontend validation on large text payloads

**Priority:** High  
**Severity:** High  

### Description
The AI assistant chat component lacks proper client-side validation for maximum character constraints. When a user submits an excessively large text payload, the application fails to execute the request but enters an indefinite "Processing" state. If a subsequent valid message is successfully transmitted, the initial pending loader remains permanently stuck in the UI timeline, causing a critical interface state desynchronization.

### Preconditions
User is on the main application page and the AI search assistant interface is initialized and active.

### Steps to Reproduce
1. Copy a large block of text (exceeding 2,000 characters) and paste it into the chat message input field.
2. Observe if any structural block, character counter, or input restriction warning appears.
3. Click the transmission button to submit the oversized payload.
4. Observe the instantiation of the "Your message is being processed..." loading animation.
5. While the loading animation remains active, input a standard brief string (e.g., "Hi") and transmit it.
6. Assess the visual continuity and state behavior of the message history panel.

### Actual Result
The application allows unrestricted submission of oversized payloads without localized validation warnings. The interface hangs indefinitely in a "Processing" loop because no server response is processed to terminate the loader. Furthermore, a state desynchronization occurs: the subsequent brief string receives a valid response, but the pending loader from the failed payload remains as a persistent artifact in the message history view.

### Expected Result
The input field must implement client-side constraints, such as a `maxlength` attribute or a visible character counter, while disabling the transmission button if constraints are breached. If a transmission fails due to payload size restrictions, the processing state must be cleared immediately to render an explicit error message (e.g., "Message length exceeds limit"). Lastly, initiating a new query must programmatically resolve or clear prior pending states.

### Environment
Web / Chrome / Desktop
