# BUG-004 – Search relevance algorithm maps "app" token to feature attributes instead of core brand keywords

**Priority:** High  
**Severity:** Medium  

### Description
A core relevance logic flaw exists within the AI search and retrieval algorithm. When a user executes a query using the truncated token "app" combined with a generational index number (e.g., "app 16"), the search engine interprets "app" as a device feature attribute (e.g., "App Control" capabilities in smart appliances) rather than mapping it to the primary global brand synonym payload. This leads to completely irrelevant search results across mismatched product verticals.

### Preconditions
User is on the main landing page with the search input interface initialized.

### Steps to Reproduce
1. Open the platform URL.
2. Navigate to the primary AI-powered search input bar.
3. Input the combined brand and model query token: "app 16"
4. Execute the search and observe the relevance sorting of the returned product items.

### Actual Result
The search engine returns top-tier indexing priority to unrelated smart home appliances, drones, and smartwatches that possess "App Control" parameters in their metadata. The algorithm completely fails to parse "app" as a keyword variation for a specific brand ecosystem, entirely missing the context of a smartphone hardware search request.

### Expected Result
* **Keyword Priority Configuration:** The token "app" should be programmatically weighed with higher relevance toward major consumer electronics brand entities via synonym mapping.
* **Category Weighting Strategy:** Smartphone and mobile hardware verticals must possess a higher structural weight parameter than secondary feature strings located inside appliance descriptions.
* **Intelligent Query Parsing:** The AI model should recognize the syntax structure of "app [number]" as a distinct generational hardware model query rather than an isolated feature filter across disparate product categories.

### Environment
Web / Chrome / Desktop
