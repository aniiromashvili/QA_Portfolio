# BUG-001 – AI search assistant persists in Georgian responses despite English system mode and explicit English queries

**Priority:** High  
**Severity:** Medium  

### Description
The AI search assistant fails to maintain the correct language context based on system configuration and active user inputs. Even when the system is set to English mode and the user submits explicit queries in English regarding product recommendations, the AI model remains locked in Georgian responses. The assistant only switches back to English after a direct, explicit correction command is given.

### Preconditions
The application interface and system settings are configured to English mode.

### Steps to Reproduce
1. Open the platform URL.
2. Click the chat button in the bottom-right corner to initialize the AI search assistant interface.
3. Send an initial conversational greeting in English: "Hi"
4. Send a single transliterated informal greeting word: "gamarjoba"
5. Submit a specific, complex product query completely in English: "which phone u recommend?"
6. Observe the response language language output generated by the AI model.
7. Send an explicit corrective directive command: "You are in English mode"
8. Re-observe the language state behavior of the assistant.

### Actual Result
Despite the system language being explicitly set to English and receiving a detailed English query for product recommendations, the AI assistant remains locked in Georgian mode, continuing to output responses in Georgian until directly commanded to switch.

### Expected Result
The AI assistant must strictly respect the global English system settings. Furthermore, the model should support dynamic language switching; even if a brief transitional word like "gamarjoba" is processed, any subsequent complex query submitted in English must automatically trigger the model to adapt and switch its output language back to English.

### Environment
Web / Chrome / Desktop
