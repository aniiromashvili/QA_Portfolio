# BUG-005 – Feature disparity and missing model selector options in AI Chat between Draft and Board view states

**Priority:** Medium  
**Severity:** Medium  

### Description
A core feature parity desynchronization exists within the AI Assistant widget layout. When the chat interface is initialized within the project "Draft" view state, the system logic correctly displays a Model Selector capability allowing users to transition between four distinct AI core version structures. However, when the user toggles the workspace into the interactive "Board" view state, the model selector restrictions degrade, trapping the user within a single default AI framework configuration.

### Preconditions
The user has initialized an active project workspace layout with structural document data and creative assets populated.

### Steps to Reproduce
1. Open the project workspace view (the application initializes into the default "Draft" editor view state).
2. Locate and click the "AI Chat" control action button in the upper-right area of the header layout.
3. Observe the lower-right baseline of the chat panel text input box to locate the active dynamic model dropdown element.
4. Expand the dropdown interface and confirm the availability of multiple distinct core models.
5. Click the workspace toggle control in the upper navigation zone to transition the current project layout into the alternative "Board" canvas mode.
6. Re-evaluate the functional behavior parameters and availability of options inside the AI Model Selector dropdown elements.

### Actual Result
A localized feature parity degradation occurs: while the default "Draft" editing session context grants the user flexible access to select between four separate AI model engines, transitioning to the interactive "Board" view configuration strictly strips away options, presenting only one rigid AI version path.

### Expected Result
The execution capability, baseline parameters, and core version selections of the AI Chat assistant ecosystem must remain entirely consistent and synchronized across all primary user interface view states. The model dropdown mechanism should expose identical functional configurations and access tokens whether accessed from the standard "Draft" layout or the alternative "Board" workspace canvas.

### Environment
* **Environment Architecture:** STG Staging
* **Hardware Specification:** Lenovo Ideapad Slim 3i (Windows 11 Pro, Build 26200)
